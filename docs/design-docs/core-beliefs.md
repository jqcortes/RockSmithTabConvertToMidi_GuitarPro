# core-beliefs.md — 設計思想・不変の原則

> このファイルに記載された原則はプロジェクト全体を貫く不変の設計思想です。
> 変更する場合は必ずチームレビューを経てください。

---

## Belief 1: タブ譜を真実の源とする

ギターバンドスコアでは**五線譜とタブ譜（TAB）が並記**されることが一般的である。
五線譜の音符認識は音域・移調の解釈ミスが発生しやすいのに対し、
タブ譜のフレット番号はフレット位置という物理的事実を表すため認識誤りが少ない。

**原則**: 五線譜とタブ譜が共存する場合、タブ譜のフレット情報を pitch の正解として採用する。
五線譜のみが存在する場合は五線譜を使用するが、音域バリデーションを必ず行う。

---

## Belief 2: 修正不要は「精度の高さ」ではなく「信頼度の正直さ」で実現する

「修正不要」の目標は「100%正確」と同義ではない。
信頼度が低いノートは MIDI に含めず警告として明示することで、
ユーザーが確認すべき箇所を明確に提示することが「修正不要体験」につながる。

**原則**: 曖昧な認識結果は無理に出力しない。品質スコアが閾値を下回った場合は
変換失敗として処理し、原因レポートを出力する。

---

## Belief 3: 前処理と後処理でエンジン限界を補う

Audiveris は優れた OMR エンジンだが、スキャン画像の歪みや
バンドスコア特有の密集記譜には限界がある。
エンジンのパラメータ調整より、**入力画像の品質向上**と
**出力 MusicXML の後処理補正**の方がコストパフォーマンスが高い。

**原則**: Audiveris 内部に手を入れるより、前後の処理層で品質を確保する。
エンジン設定変更は最後の手段とする。

---

## Belief 4: パイプラインはステップ単位でキャッシュ・再実行可能にする

1枚のバンドスコア処理に数分かかる場合がある。
後処理の改善のたびに OMR を再実行するのは非効率である。

**原則**: 各ステップの出力をディスクにキャッシュし、
特定ステップからの再実行を可能にする。
Audiveris の `.omr` ブックファイルも成果物として保存する。

---

## Belief 5: ギター特有の奏法は MIDI で「近似」する

チョーキング・ハンマリング・スライド等のギター奏法は
MIDI の表現能力の範囲内で最善の近似を行う。
完全な再現は不可能であることを前提とし、
**演奏意図が伝わる近似**を目標とする。

**原則**: 奏法の MIDI マッピングは `config/instrument_map.yaml` で
設定可能にし、ユーザーがカスタマイズできるようにする。

---

## Belief 6: バッチ処理を第一市民とする

単発変換より、アルバム単位・複数スコアの**バッチ処理**を主要ユースケースとする。
GUI は補助的な確認ツールとして位置付け、コア機能は常に CLI から利用可能にする。

**原則**: すべての機能は CLI から呼び出し可能でなければならない。
